Game shaders

A shader is a small program that decides what color each part of the picture is. A game can bring its own, and change it while the game runs: save the file and the picture changes. You need a game to put it in; make one first if you have not.

Two kinds of shader

A screen effect changes the finished picture: it is handed each pixel of what the game drew, and says what color to show instead. Black and white, a vignette, a heat haze and a sepia photograph are screen effects. Several can be on at once, and they run in the order you turned them on.

A surface shader changes one material of your level: everything in the level that wears that material. It is handed what the material looks like at that spot (its color, which way it faces, how shiny it is, how much light it gives off) and says what it should look like instead. The engine still does the lighting, shadows, fog and weather.

Shaders are written in WGSL, the shading language the engine uses itself, and each is one function in a file in your game's shaders folder. Which kind a file is comes from how your script asks for it, not from anything in the file. A file holds one function, `screen` or `surface`; if you need both, put the other in its own file.

A first screen effect

Make a folder called shaders in your game's folder, and in it a file called gray.wgsl:

shaders/gray.wgsl 
fn screen(in: ScreenIn) -> vec3f {
    // How bright this pixel is, as one number.
    let gray = dot(in.color, vec3f(0.2126, 0.7152, 0.0722));
    return vec3f(gray);
}

Add this line to main.luau, outside any function, above the line that requires the pause menu (that one stays last):

main.luau 
game.shaders.screen("gray")

The running game turns gray. Change the last line of the shader to return vec3f(gray) * 0.5; and save again: it gets darker, with no restart. The name in the quotes is the file's name without .wgsl.

A first surface shader

A surface shader needs the name of a material in your level. A level made in Blender has one for each material you made there. A new game's level has one called Red, and this shader makes it glow:

shaders/glow.wgsl 
fn surface(in: SurfaceIn) -> Surface {
    // Start from what the level's material says here.
    var out = in.surface;
    // Light the surface gives off itself.
    out.emission = vec3f(1.0, 0.3, 0.0);
    return out;
}
main.luau 
game.shaders.surface("glow", "Red")

Do not know the names? Write any name in that line and run lore check: if the level has no material of that name, it lists the ones it has. Names must match letter for letter, capitals included.

Shader error in shaders/glow.wgsl:

  The level has no material named `Rde`.
  Hint: Did you mean `Red`? The level's materials are: Floor Light, Floor Dark, Wall, Platform, Ramp, Cover, Red, Blue.
  Nothing is changed until a level with that material is loaded.

Only what the camera sees changes: a glowing surface does not light the room around it, and it casts the same shadows as before.

Everything a shader is given

A screen effect is handed in, a ScreenIn, and returns a vec3f, the color to show. Light is linear and not limited to 1: a bright lamp or the sun is far above 1, and tone mapping brings it down afterwards.

In a screen effectWhat it is
in.uvWhere on the picture, 0 to 1: x to the right, y down.
in.colorThe picture here, in linear light. It may be far above 1.
in.distanceMetres from the eye to what is drawn here. For sky it is 1,000,000.
in.timeSeconds on the renderer's own clock, which starts again each hour.
in.sizeThe picture's size in pixels.
picture(uv)The picture somewhere else, as a vec3f: for a blur or a ripple.
distance_at(uv)Metres from the eye to what is drawn at uv.

A surface shader is handed a SurfaceIn and returns a Surface. It usually starts from in.surface and changes some fields.

In a surface shaderWhat it is
in.surfaceWhat the level's material gave here: a Surface, below.
in.positionWhere this point is in the world, in metres.
in.uvThe material's first UV map.
in.viewA unit vector from the surface to the eye.
in.distanceMetres from the eye.
in.timeSeconds on the renderer's own clock: the same as in a screen effect.
A Surface hasWhat it is
colorThe color light picks up, in linear light, 0 to 1.
normalWhich way it faces, in the world, length one.
roughness0 is a mirror, 1 is chalk.
metallic0 is not metal, 1 is bare metal.
emissionLight it gives off itself.
alphaCut-out and see-through materials use it; solid ones do not.

Anything you return is tidied: negative color and emission become 0, alpha is held between 0 and 1.

Values you can change

A value is a number or color the shader declares, so the script can change it without touching the shader. Declare each with a line near the top that starts //! param, and read it in your function as params. and its name:

shaders/heat.wgsl 
//! param strength: f32 = 0.5 range 0..1
//! param tint: color = #ff8800

fn screen(in: ScreenIn) -> vec3f {
    let gray = dot(in.color, vec3f(0.2126, 0.7152, 0.0722));
    return mix(in.color, gray * params.tint, params.strength);
}

The line is //! param name: type = default, and may end with range low..high for a number.

TypeWhat it holdsA default looks like
f32A number. The only type that takes a range.0.5
vec2f, vec3f, vec4fTwo, three or four numbers, such as a direction.(1, 2, 3)
colorA color. In the shader it is a vec3f in linear light.#ff8800 or a name such as orange

Hex codes and color names are the colors you see in an editor (sRGB); the engine turns them into linear light for you.

Setting values from the script

Give the values in a table when you turn the shader on, and change any of them later, as often as every picture, with shader:set. Nothing is rebuilt.

local heat = game.shaders.screen("heat", { strength = 0.3, tint = "orange" })

game.onDraw(function()
    -- Gets stronger and weaker, once every three seconds or so.
    heat:set("strength", 0.5 + 0.5 * math.sin(game.time() * 2))
end)

A color can be a name, a hex code in quotes, or a table of three numbers; numbers are read as sRGB like hex codes. A vec3f takes vector.create(1, 2, 3) or {1, 2, 3}. A number outside the shader's range is an error, not quietly cut to fit. A value you leave out is the shader's own default; turning the shader on again with a table sets exactly those values and puts the rest back to the defaults.

Text from the script

A shader does not have to be a file: give its text as code. Call again later with new text and it is replaced.

game.shaders.screen("pulse", { code = [[
fn screen(in: ScreenIn) -> vec3f {
    return in.color * (1.0 + 0.3 * sin(in.time * 4.0));
}
]] })

Turning one off, and saving the script

heat:remove() turns the shader off. Asking for it again turns it on, and the handle you kept works again.

What a save of main.luau does depends on where the line is. A shader asked for at the top of the file comes and goes with that line: delete the line, save, and it is off. A shader turned on from inside a function (a menu, a timer, game.onStart) is still on after a save, as a lamp is, until you remove it. Saving the shader's own file changes the running game and keeps the values that still fit.

When there is a mistake

A mistake never turns the picture black or pink. The last version that worked keeps drawing, the message is shown in the top-left corner of the game's window and in the terminal, and it goes away when you save a version that works. Both kinds show at once, the script's first.

lore check compiles every shader your game has, with no graphics card, so it finds these without opening a window. A mistake in the shader's own text:

Shader error in shaders/heat.wgsl, line 5:

     5 | let gray = dot(in.colour, vec3f(0.2126, 0.7152, 0.0722));
       |                   ^

  `ScreenIn` has no field `colour`.
  Hint: Did you mean `color`?

A mistake in the script, here a misspelled value name in a shader that has strength:

[ERROR] Script error in main.luau, line 51:

    51 | game.shaders.screen("heat", { strenght = 0.3 })

  The screen effect "heat" has no value called `strenght`. Did you mean `strength`? Write it like this: game.shaders.screen("heat", { strength = 0.5 })
  Fix this and save the file: the game picks it up by itself.

A shader with no //! param lines says instead how to add one.

lore check also compiles the other files in shaders that the script did not turn on, so a shader that a menu turns on is checked too, and warns about a file with neither a screen nor a surface function in it.

Limits, and what is not possible yet

  • 8 screen effects and 8 surface shaders at once, with 32 values and 64 KiB of text each.
  • No loop and no while, and no for without an end: a shader that never finishes would freeze the picture. Use for with a fixed count, as in for (var i = 0; i < 8; i++) { … }.
  • A material has one surface shader: asking for another on the same material replaces it.
  • A screen effect's color is held between 0 and 65504.

Not possible yet: pictures (textures) as values, shaders for the sky, water or the HUD, moving a level's vertices, and a library of helpers such as noise. A surface shader changes only what the camera sees: not the shadows a surface casts, the light it bounces, or its reflection in water.

Two shaders to read and copy are in the alley example: old_photo.wgsl, a screen effect with values, and glow_bands.wgsl, a surface shader whose bands slide up with the time. Its debug menu turns them on from a function: debug_menu.luau.
