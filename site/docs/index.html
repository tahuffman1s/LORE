Docs

LORE is early, so these pages only describe what runs today. It began as an engine for multiplayer shooters, so today everything is seen in first person. LORE is single-player only: nothing connects to anything, and there are no teams, rounds or scores to win. Third person, NPCs, saving and stories are planned. New here? Start with the tutorial.

Your first stepsMake a game, walk around it, change it while it runs, put a counter on the HUD, play a sound and place where you start. About ten minutes.

Install

There are no downloads yet: LORE is built from its source code, which takes one command once Rust is installed. Step 1 of the tutorial walks through it.

cargo install --git https://github.com/tahuffman1s/LORE lore

Run the same line again to update. It needs Linux or Windows and a graphics driver with Vulkan 1.3; macOS is not ready.

Commands

Each one explains itself with --help, as in lore run --help. A command that takes a game uses the folder you are in unless you name another.

CommandWhat it does
lore new my-gameCreates a game that is ready to play, in a new folder called my-game, with a small level in it.
lore runPlays the game in its level, the level.glb in the game's folder (a glTF Binary file, which Blender exports). It loads the script again every time you save it.
lore editOpens the game's level to fly around, over a grid with lines a metre apart. Hold the right mouse button to look; W A S D fly, or use a gamepad's sticks. A list on the left names everything in the level: click a name to see where it is and how big it is, double-click to fly to it. Place a spawn here puts a spawn point on the ground where the camera looks; choose it to change its type, name, position and facing. Drag its mark in the picture to move it and the tip of its line to turn it, on a grid the Snap button changes; tick Click in the picture to place to place by clicking. On a gamepad, A places where you look, X carries what you look at and puts it down, B puts it back, LB and RB turn it and Y changes the snap. What you place is saved in map.toml in the game's folder as you go, and a game that is running picks it up. F5, or Select on a gamepad, plays the level from where the camera is, and the same key or button comes back to editing with the camera and the map as you left them.
lore checkTests the game without opening a window: runs a second of it with its player in it, presses every action in turn, tells the script of things that did not happen (a shot that hits a training dummy ten metres in front of the player, one that hits a wall, a reload, and the player dying and being put back at a spawn point) so every game.on… function is called at least once, plays the start again with pictures drawn at other paces, loads its level and its map file and starts the player at each spawn point, and fails if the script has a mistake, its rules depend on the frame rate, the level cannot be read or the map file has a mistake.
lore packageOn Linux, writes a download of the game to its dist folder, which players unpack and run without installing LORE.
lore controlsShows which key and button does what, and where the text file is that changes it. It makes the file if there is none; games read it when they start, and again whenever you save it while they run.
lore demoOpens a test window that shows what your keyboard, mouse or gamepad is doing.
lore benchMeasures how fast this computer draws a built-in test scene.

Scripting

A game is a folder with a main.luau in it, where the game starts, written in Luau. Everything the engine offers a script is in one table called game.

In a scriptWhat it is for
game.onStart, game.onTick, game.onReloadRun your code when the game starts, 60 times a second, and when the script is saved.
game.after, game.every, game.tween, game.time(), game.onDrawWaits, repeats, numbers that move and the game's clock, so a script never counts time: see Time.
game.keep("saved", { best = 0 })Gives a table that keeps what you put in it when the script is saved and reloads; everything else in the file starts over. It holds numbers, text, true and false, game.player, and tables of those, until the game is closed.
game.playerThe player. There is one, there from the first line of the script: game.player.name, game.player.position (where their feet are, in metres, with y up) and what they hold. There is no list of players and nobody joins or leaves: a script that asks for game.players(), game.onPlayerJoin or game.onPlayerLeave gets an error on that line that says so and what to write instead.
game.onSpawn(function() … end)Runs your code when the player is put at a spawn point: on the first tick, right after game.onStart, and after dying. Nothing has health yet, so nothing in the engine kills the player; if they do die they are put straight back at a spawn point with what they held.
game.player:giveWeapon("rifle"), game.player:takeWeapon()Puts a weapon in the player's hands, or empties them. The engine's weapons are "rifle", "pistol", "shotgun", "rocket launcher" and "grenade". The player fires with "fire", aims with "aim" and reloads with "reload"; game.player.weapon, game.player.ammo and game.player.reserve say what they hold. Nobody holds a weapon until a script hands one out.
game.weapon("smg", { … })Makes a weapon of your own, or changes one of the engine's: game.weapon("smg", { from = "rifle", damage = 22, roundsPerMinute = 900 }) is a rifle with those two numbers changed. Fire mode, magazine, reload, damage over distance, spread, recoil, and how a rocket or grenade flies can all be set.
game.onWeaponFire, game.onWeaponHit, game.onWeaponReloadRun your code when a shot is fired, when one lands and when a reload starts. The first and the last are handed who did it, which today is always the player. A hit says who fired (hit.shooter), who was hit (hit.victim: nobody, for a wall), with what, where on the body, and what it is worth. Until a game has people in it there is nobody but the player to hit; lore check tells your script of a pretend shot at a training dummy so that code runs. Nobody is hurt yet: until there is health (#40), your script decides what a hit means.
Teams, rounds and scoresThere are none: a script that asks for game.mode, game.team, game.round, game.onKill or game.player.score gets an error on that line that says so and what to write instead.
game.inputWhat the player is pressing, by action name ("jump", "fire", "move"), the same for keyboard, mouse and gamepad.
require("./weapons")Splits a game over files: runs weapons.luau, the file beside the one that asks, once, and gives back what that file ends with, such as return weapons. Paths start with ./ or ../ and stay inside the game's folder. Saving any of the files reloads the game.
game.audio.play, game.audio.playAtPlays a sound by name: game.audio.play("music/theme", { volume = 0.4, loop = true }) is as loud wherever the player stands, and game.audio.playAt("door", vector.create(10, 1, -4), { range = 30 }) comes from a place in the world, in metres. Both give back a sound that sound:stop() ends, and game.audio.stopAll() stops every sound the script has played. A sound is a WAV or Ogg Vorbis file in the game's sounds folder, named without .wav or .ogg. Music goes in sounds/music as Ogg Vorbis and follows the player's music volume, and a long Ogg Vorbis file is decoded as it plays, not held in memory whole; the starter sounds "footstep", "gunshot", "landing", "dry-fire" and "reload" need no file, and a file with one of those names replaces it.
game.hud.text, game.hud.bar, game.hud.boxPuts a piece on the HUD, over the game: local score = game.hud.text("0", { at = "top" }) is a line of text, game.hud.bar(1, { at = "bottom left", color = "red" }) a bar that is full at 1 and empty at 0, and game.hud.box({ at = "center", width = 6, height = 6 }) a plain box. Make each once, at the top of the file, and change it as the game goes on: score.text = points, health.value = 70 / 100, health.color = "orange", score.visible = false, score.down = 40, score:remove(). at is "top left", "top", "top right", "left", "center", "right", "bottom left", "bottom" or "bottom right"; right and down move it from there, in pixels on a screen 1080 high. A colour is a name such as "red" or a hex code such as "#ff8800".
game.input.rumbleShakes the player's gamepad: game.input.rumble(0.2, 0.6, 0.1) is the heavy motor, the light motor, then seconds. On Linux and Windows, in lore run; not on macOS yet. The player's Rumble setting scales it, down to off.
game.input.useSet, game.input.currentSetSwitches which set of actions hears the player: game.input.useSet("menu") while a shop or inventory of your own is open, where the menu_... actions work and the mouse is a pointer, and game.input.useSet("gameplay") to go back. game.input.currentSet() is the name of the set the game is in. A script cannot add actions or sets of its own yet.

Time

The game's rules run in game.onTick and in timers, 60 times a second on every computer however fast it draws, so a game plays the same on a slow laptop and a fast desktop with nothing multiplied by a frame time. To wait or repeat, write game.after(3, …) or game.every(0.5, …), and for a number that moves game.tween(0, 100, 1); game.time() is the seconds the game has run, and the computer's own clock (os.clock) is not there to read. game.onDraw runs once for every picture drawn and is only for showing the game: a tween read there is smooth between ticks, and changing the game there is an error that says where to move the line.

game.onStart(function()
    print("The door opens in 3 seconds.")
    game.after(3, function()
        print("The door is open.")
    end)
end)

game.every(10, function()
    print(game.time() .. " seconds played")
end)

A timer is called on the first tick that is not before its time, and a repeating one keeps its beat for ever. timer:cancel() calls one off. Saving the script drops the timers started inside functions (the terminal says how many) and starts the ones at the top of the file again; nothing a script can draw on screen is built yet, so for now game.onDraw has only print and sounds to show with.

The full list, with every setting and what each function is given, is lore.d.luau. A copy is in every game's folder, which is what gives your editor autocomplete: in VS Code, install the Luau Language Server extension and open the game's folder.
