Docs / Tutorial

Your first steps

You will make a game and walk around it, change it while it runs, put more on the screen, give it a sound, and choose where you start by placing a spawn point in the editor.

  • About ten minutesafter a one-off install that takes about five more
  • Linux or Windowswith a graphics driver from the last few years
  • No experience neededevery command is here to copy

What you get today

LORE is early. At the end of this page you stand in a small level of your own game, seen through your own eyes, with solid walls, ramps to climb, a welcome and counters on the screen that your script keeps, a sound your script plays, and a starting place you put there yourself. Nobody else is in the world yet, and there is nothing to fight or talk to: people, quests and saving are still being built.

Steps

  1. Install LORE
  2. Make a game
  3. Walk around it
  4. Change it while it runs
  5. Put more on the screen
  6. Play a sound
  7. Place where you start

1Install LORE

There is no download yet, so your computer builds LORE from its source code. That needs two things installed first, and you only do this once.

Everything on this page is typed into a terminal. On Linux, open the program called Terminal or Konsole. On Windows, press the Windows key, type PowerShell and press Enter.

Rust, which builds the engine

Follow the one step at rustup.rs, then close the terminal and open a new one. On Windows it also offers to install the Visual Studio build tools: say yes.

On Linux only: a compiler and two libraries

Ubuntu, Debian, Mint 
sudo apt install g++ libudev-dev libasound2-dev
Fedora 
sudo dnf install gcc-c++ systemd-devel alsa-lib-devel

LORE itself

cargo install --git https://github.com/tahuffman1s/LORE lore

This is the slow part: one to five minutes on most computers, longer on an old one. Lines starting with Compiling scroll past while it works. Nothing is wrong while they keep coming.

You should see

The last line starts with Installed package. Check that the command is there:

lore --version
lore 0.0.0
It says cargo is not found, or lore is not found

The terminal was open before Rust was installed. Close it, open a new one and try again.

It stops with linker `cc` not found or failed to run custom build command

A compiler or library is missing. On Linux, run the line for your system under “a compiler and two libraries” above. On Windows, run the Rust installer again and let it install the Visual Studio build tools. Then run the cargo install line again; it carries on from where it stopped.

2Make a game

lore new first-steps

You should see

Created the game "first-steps" in …

Play it:
    cd first-steps
    lore run

Then open main.luau in an editor, change something and save: the running game updates by itself.

A game is a folder. Yours is called first-steps, and two files in it matter today: main.luau, the game's script, and level.glb, the place it happens in. Go into the folder, and stay in it for the rest of this page:

cd first-steps

3Walk around it

lore run

You should see

A window opens on the game's level: a small walled garden with a tower ahead of you, a glowing light on top of it, and a house off to one side. You start at the south end, looking at the tower. Across the top of the window it says Welcome to first-steps!, with a hint under it that goes away after a few seconds, and in the bottom left corner it says Jumps: 0. The terminal greets you too, among a few other lines:

[INFO] Playing ./main.luau. Edit it, or a script it requires, and save to see changes right away.
[INFO] Welcome to first-steps! Click the game window so it can see your mouse.
[INFO] Jump: Space, or the bottom face button on a gamepad.
[INFO] Fire: left mouse button, or the right trigger.

On Windows the first line says .\main.luau. A title screen comes first: press Enter (or the bottom face button on a gamepad) on Start. Then click the window, and look around with the mouse and walk with W A S D. A gamepad works too: left stick to walk, right stick to look. The walls and the house are solid, a ramp and some steps lead up to a terrace, and you can hear your own footsteps. Press Space (or the bottom face button on a gamepad) a few times: the number in the bottom left counts your jumps, and the terminal does as well:

[INFO] Jump number 1
[INFO] Jump number 2

All of that text comes from your script. Esc, or Start on a gamepad, pauses the game, gives the mouse back and opens its menu: Resume, Settings and Quit. The menu comes with LORE, and your script can change it: game.pauseMenu.title names it and game.pauseMenu.addRow adds a row of your own. Choose Resume, and leave the game running for the next step.

It says Could not find Vulkan on this computer, or that Vulkan is too old

LORE draws with Vulkan 1.3, which comes with the graphics driver. Update the driver for your graphics card and run lore run again. On Linux, also install the Vulkan loader: sudo apt install libvulkan1 or sudo dnf install vulkan-loader.

It says There is no game here

The terminal is not in the game's folder. Run cd first-steps, then lore run again.

4Change it while it runs

Open first-steps/main.luau in any text editor: Notepad and Text Editor are fine. Find this line, the one that writes the jump count on the screen:

        jumps.text = "Jumps: " .. saved.jumps

Change the words inside the quotes, and save the file:

        jumps.text = "Boing! " .. saved.jumps

You should see

The terminal says the game took the new version, without restarting, and the welcome comes up on the screen again for a few seconds. If you had jumped twice:

[INFO] Reloaded main.luau.
[INFO] main.luau was saved and loaded again. Jumps so far: 2

Jump in the game, and the corner now says Boing! 3. The count was not lost because the script keeps it in a game.keep table; everything else in the file starts over on a save.

Now break it on purpose. Change game.onTick to game.onTik and save:

[ERROR] Script error in main.luau, line 40:

    40 | game.onTik(function()

  game.onTik does not exist. Did you mean game.onTick?
  The game keeps running the last version that worked. Fix this and save the file: it reloads by itself.

The game did not crash, and the message says which line and what to try. The same message is in the top-left corner of the game's window, so you see it without looking away from the game. Put the c back, save, and it reloads: the message in the window goes away. Leave the game running.

5Put more on the screen

Text, bars and boxes drawn over the game are its HUD, and your game already has some: the welcome and the jump count. Add one more piece, a count of your shots in the top right corner. Find the line that makes the jump count:

local jumps = game.hud.text("Jumps: " .. saved.jumps, { at = "bottom left" })

Add these two lines under it. The first starts a number at 0, the second puts it on the screen, pinned to the top right:

local shots = 0
local shotsText = game.hud.text("Shots: 0", { at = "top right" })

Then find the line that plays the shot's sound:

        game.audio.play("gunshot")

Add these two under it, and save:

        shots += 1
        shotsText.text = "Shots: " .. shots

You should see

The game is still running, and Shots: 0 is in the top right of its window. Click the left mouse button, or pull the right trigger, and it counts up. Unlike the jumps it starts from 0 again on every save, because shots is not in the game.keep table.

Try the options: at is where the text is pinned ("top left", "bottom right", "center" and so on), down moves it from there, size makes it bigger and color = "yellow" colours it. Save after each change and watch the window. A game.hud.bar is made the same way, for something like health.

The terminal shows a Script error

The message names the line and what to try. The two new lines at the top have to sit on their own lines, outside any function; the two under game.audio.play have to sit inside the if, above its end.

6Play a sound

The shot already has a sound. Give the jump one too. Find this line:

        saved.jumps += 1

Add this line under it, and save:

        game.audio.play("reload")

You should see

Nothing new to see: jump, and you hear a click-clack with every jump. "reload" is one of the sounds the engine comes with, like "gunshot" for the shot and the footsteps you have been hearing.

A sound of your own is a WAV or Ogg Vorbis file in a folder called sounds inside the game's folder: sounds/boing.wav is played with game.audio.play("boing"). Now close the game's window, and let the engine try the script out. This command opens no window: it runs the game for a moment, presses every button for you, and tells you if anything in the script went wrong.

lore check

You should see

[INFO] Jump number 1
[INFO] Jump number 2
[INFO] Fire! Moving 0, 0
main.luau is fine: it loaded and ran for 60 ticks (1 second of game time) with its player in it and no errors.

More lines follow, saying what the check tried and what it did not. It jumped twice because two things are bound to jump: a key and a gamepad button.

It says main.luau has a mistake

The lines above that message name the line and what to try. The new line has to sit inside the if that checks for a jump, above its end, with its quotes and brackets as shown.

7Place where you start

The script says what happens; the editor says what is where. Open your game's level in it:

lore edit

You should see

A window opens on the same level, with a panel on the left that lists everything in it. Under map.toml the panel says Nothing placed yet.

Hold the right mouse button and move the mouse to look around; W A S D fly. Fly up onto one of the platforms, look down at its floor, and click Place a spawn here on the left. A mark appears where you were looking, and the panel now says 1 placed: 1 spawn: that is where the game starts. Drag the mark to move it, and the tip of its line to turn the way you will face.

There is no save button. What you place is written as you go to map.toml in the game's folder, a text file you can read and change by hand. With one spawn point it looks like this, with an id of its own and the place you chose:

map.toml 
version = 1

[[entity]]
id = "k3f9x2"
type = "spawn"
position = [0.0, 0.0, 0.0]
facing = 90.0

Press F5 to play from where the camera is, without leaving the editor, and F5 again to come back. Then close the editor's window and play the game the usual way:

lore run

You should see

You start on the platform, at your spawn point, facing the way its line pointed, with your counters on the screen. lore check now has a line about the map as well:

map.toml is fine: 1 placed: 1 spawn. The player starts at one of its spawn points.
I still start at the end of the level

No spawn point was placed, so the level's own starting places are used. Run lore edit again: if the panel on the left says Nothing placed yet, look at a floor and click Place a spawn here.
