# {name}

A game made with [LORE](https://github.com/tahuffman1s/LORE). The game is a Luau script, `main.luau`, and a level, `level.glb`.

## Commands

```sh
lore check    # run main.luau and load level.glb and the sounds without a window; exits non-zero and prints the error if any has a mistake
lore run      # play the game in a window (a person has to look at it and close it)
lore package  # write a download for players to dist/ (Linux only so far); refuses a script with a mistake
```

Run them from this folder (or name it: `lore check path/to/this-folder`).

Run `lore check` after every change to `main.luau` and fix what it reports before saying the change is done. It runs the start handler and one second of ticks with nothing pressed, calls the `game.onDraw` functions for one picture, then presses, holds and lets go of every action, one at a time, pushes each stick all the way round and moves the mouse, so the code inside `if game.input.justPressed("jump")` runs too; after an error in that code it prints which action it was pressing. Then it holds each action while pressing each other one, both ways round, so `if game.input.pressed("aim") and game.input.justPressed("fire")` runs too, and prints which two it was holding and pressing after an error there. Then it tells the script of things that did not happen, as the engine would if they had: a training dummy stands ten metres in front of the player, who fires one shot that hits it (`hit.victim` is the dummy, a character called "Training dummy") and one that hits a wall (`hit.victim` is nil), reloads, dies and is put back at a spawn point, so every `game.on...` function in the script is called at least once. No level is walked and nothing is aimed for those. Last it plays the first second and the presses four more times with `game.onDraw` called at other paces, and fails if the rules did anything different: that means a rule reads a variable that a `game.onDraw` function changes, and the line that changes it belongs in `game.onTick`. (A script that calls `math.random` in its rules is told this could not be judged; that is not a failure.) Expect the script's own prints for those presses in the output. It does not hold three actions together, and it does not reach a branch that needs more than a press or those two pretend shots, such as a shot to the head or an explosion. A mistake there is not caught: read that code carefully, and ask the person to try it with `lore run`.

Do not start `lore run` yourself unless asked: it opens a window and does not exit until the window is closed. While it is running, saving `main.luau` reloads the game, so there is no need to restart it.

## Writing scripts

- `lore.d.luau` is the complete list of what a script can call, with an example for each. Read it before using anything on `game`; if it is not in that file, it does not exist. Do not edit the file: `lore run` rewrites it when the engine is updated.
- Scripts register functions: `game.onStart`, `game.onTick(function(step) ... end)`, `game.onReload`. A tick is always the same length (`step` seconds, 60 a second) on every computer, so the game's rules go there.
- Time: never count seconds, multiply by a frame time or read a clock (`os.clock` and `os.time` are errors). Wait with `game.after(3, function() ... end)`, repeat with `game.every(0.5, function() ... end)`; both give a timer that `timer:cancel()` calls off. `game.time()` is the seconds the game has run. `local shown = game.tween(0, 100, 1)` is a number moving from 0 to 100 over a second: read `shown.value` and `shown.done`, send it on with `shown:to(50, 0.3)`. `game.onDraw(function() ... end)` runs once per picture and is only for showing things: anything that changes the game there (weapons, timers, tweens) is an error, so put it in `game.onTick` or another `game.on...` function. Saving the script drops timers started inside functions; start long-lived ones at the top of the file. `lore check` only lives a few seconds of game time, and says how many timers had not come due.
- LORE makes single-player games: there are no game modes, teams, rounds or scores to win. `game.mode`, `game.team`, `game.teams`, `game.round`, `game.onRoundStart`, `game.onRoundEnd`, `game.onKill`, `game.player.team`, `game.player.score` and `game.player:addScore` do not exist, and using one is an error on that line that says what to write instead. Rules go in `game.onTick`, waits in `game.after` and `game.every`, and a count of your own in a variable (or a `game.keep` table) shown with `game.hud.text`.
- Weapons: nobody holds one until the script hands it out, usually `game.onSpawn(function() game.player:giveWeapon("rifle") end)`. The engine's weapons are `"rifle"`, `"pistol"`, `"shotgun"`, `"rocket launcher"` and `"grenade"`; the player fires with the `fire` action, aims with `aim` and reloads with `reload`, and the engine does the firing, recoil, spread, reloading and flight. Make or change one near the top of the file: `game.weapon("smg", { from = "rifle", damage = 22, roundsPerMinute = 900, magazineSize = 25 })` (every setting is listed in `lore.d.luau`; times in seconds, distances in metres, angles in degrees). `game.player.weapon` is the name held or nil, `game.player.ammo` and `game.player.reserve` are its rounds, Each `giveWeapon` adds to what the player carries and brings it up (one of each kind; giving one they have fills it up again), and `next_item`/`previous_item` (the mouse wheel, the d-pad left and right) go round what they carry; a weapon brought up fires after its `raiseTime`, and a reload of the one put away is cut short. A grenade (any weapon made with `thrown = true`) handed to someone already holding a weapon stays on their belt and is thrown with `use_item` (G, the right bumper) while the weapon stays up. `game.player.weapons` lists what they carry, `game.player:drawWeapon("pistol")` brings one up, `game.player:putAwayWeapon()` empties the hands, `game.player:takeWeapon("rifle")` takes one away and `game.player:takeWeapon()` all of them, `game.player:ammoOf("grenade")` gives a carried weapon's rounds and spares, `giveWeapon("pistol", { draw = false })` hands one over without bringing it up, and `game.player:setMaxWeapons(2)` limits what is carried (another, when full, replaces the one in the hands). `game.player:setAbility("switchWeapons", false)` frees the item buttons for the game's own use. React with `game.onWeaponSwitch(function(who, weapon, before) ... end)` (heard on the tick after the change), and with `game.onWeaponFire(function(shooter) ... end)`, `game.onWeaponReload(function(shooter) ... end)` (`shooter` is who did it, which today is always `game.player`) and `game.onWeaponHit(function(hit) ... end)`, where `hit` has `shooter`, `victim` (nil when the level was hit; `game.player` when their own explosion caught them; nobody else is in a running game until LORE has NPCs), `weapon`, `damage`, `part` (`"head"`, `"body"`, `"legs"` or nil), `position`, `distance` and `explosion`. A weapon names its sounds with `fireSound = "twang"`, `reloadSound`, `emptySound` and how far its shot carries with `heardWithin = 20` (metres, 150 to start). A hit takes the victim's health through the same path as every other hurt (see Health below). What is held is drawn: the engine's weapons as plain stand-ins, or a model of the game's own with `model = "models/pistol.glb"` in `game.weapon` (grip at the origin, muzzle along -Z, top along +Y, in metres; in first person it is drawn low in front of the eyes, in third person at the right shoulder, and the body's own arms hold it: the right hand on the grip, the left on the fore-end of a long gun or cupping the right on a short one, and a thrown weapon in one hand; `hands = "one"` or `"two"` and `support = vector.create(0, -0.03, -0.25)` (where the left hand goes, metres from the grip) say otherwise). It moves as it is used, with nothing to write: kicked by each shot, swaying with the view, bobbing with a walk, tipped through a reload, lifted when brought up. `action = "auto"` (the default: a slide or bolt thrown back by each shot, held back when empty), `"bolt"` (worked by hand between shots), `"pump"` or `"none"` says how it is worked, and the parts of a model named with `slide`, `bolt`, `pump`, `magazine`, `trigger` or `hammer` in their names move so; each shot throws a spent case out of `ejectAt` (`ejects = false` for none). A thrown weapon (a grenade) is armed when its button is pressed and thrown when it is let go, wound back in the hand meanwhile, the body following through. `arming = "throw"` (the default: the fuse starts as it leaves the hand) or `"pull"` (it starts at the press, as a stick grenade's cord: holding cooks it, and too long goes off in the hand); `spin = "tumble"`, `"end over end"` or `"none"` says how it turns as it flies, drawn with its model and lying where it lands until it goes off. `game.player.armed` is the seconds it has been held armed, or nil. Do not write your own fire-rate timers or ammo counters. The player's view does not show recoil yet, and `lore check` fires two pretend shots rather than pulling the trigger of a real weapon, so try shooting with `lore run`.
- There is one player, `game.player`, there from the first line of the script: `game.player.name`, `game.player.position` (a vector: where their feet are, in metres, y up; read it, it cannot be set), and what they hold. There is no list of players and nobody joins or leaves: `game.players()`, `game.onPlayerJoin` and `game.onPlayerLeave` do not exist, and using one is an error on that line that says what to write instead.
- `game.onSpawn(function() ... end)` is called each time the player is put at a spawn point: on the first tick, right after `game.onStart`, and again whenever they are sent back to one, keeping the weapon they held. Its function takes nothing (writing `function(player)` there is an error); use `game.player` inside. Nothing happens on death unless the script says (`game.onDeath`). `lore check` is how a `game.onSpawn` function is tried a second time.
- Health: every character has `health` and `maxHealth` (100) and `dead`; change them with `setHealth`, `setMaxHealth`, `heal(n)` and `damage(n, { from = who, how = "spikes" })`. Weapons, hard landings (from about 6 m) and `damage` all hurt through one path, heard by `game.onDamage(function(hurt) ... end)` (`hurt.victim`, `.amount`, `.from`, `.how`, `.died`) and `game.onDeath(function(victim, killer) ... end)`.
- The body and the camera: the player has a body (LORE's mannequin until `game.player:setModel("mannequin_female")` or a `.glb` of the game's own). `game.player:setView("third")` (or `"first"`) chooses where the camera is, `game.player:allowViewSwitch(true)` gives the player the switch_view button (F, or View/Select), `game.player:setFacing("aim")` (or `"move"`) chooses whether the body turns to the camera or to where it walks, and `game.player:setCamera({ distance = 4, shoulder = -0.45 })` hangs the third-person camera. `game.player:hold("sword")` puts a thing in the player's right hand, seen in both views (`"sword"`, `"staff"`, `"torch"`, or a .glb file of the game's made with its grip at the origin and its length pointing up; `{ hand = "left" }` for the other hand, `nil` for empty hands; read it back as `game.player.holding`). It is only what is seen: `swing` and `giveWeapon` say what the hands do. `game.camera.fixed(vector.create(0, 6, 12), game.player, { seconds = 1 })` puts the camera somewhere else, looking at a place or a character (`fov` for a long lens), `game.camera.follow(someone, { distance = 6, height = 3 })` trails a character, and `game.camera.reset(1)` gives the view back to the player; each can travel there over `seconds` instead of cutting, and `game.camera.shot()` says which is on. More shots on the same table: `game.camera.topDown(game.player, { height = 18 })` (overhead, north up), `game.camera.sideOn(game.player, { distance = 12, angle = 90 })` (a side-scroller's camera, looking along `angle` degrees left of north), `game.camera.orbit(game.player, { distance = 4, speed = 30 })` (circling a place or a character) and `game.camera.path(game.things("camera_path"), { over = 8, at = game.player })` (along 2 to 16 vectors or map markers; `loop = true` goes round again). `steer = true` on `fixed`, `topDown` and `sideOn` makes forward mean away from the camera. A zone switches shots by calling one from its `onEnter`. Walking, running, crouching, jumping, falling, landing and swimming are animated with no code. `game.player:play("wave")` plays one of `game.player.clips` (options `fade`, `speed`, `loop`, `keepWalking`), `game.player:stop("wave")`, `game.player:isPlaying("wave")`, and `game.player:onMoment("left_foot_down", function(clip) ... end)` hears marked moments.
- Melee: `game.player:swing("sword_attack", { damage = 25, reach = 0.9 })` plays a blow and hurts what the striking hand or foot passes through, once each; `game.player:block(true)` raises the guard against blows from in front; `game.player:lockOn(enemy)` holds the camera on someone (`nil` lets go).
- Functions on the player take a colon: `game.player:giveWeapon("rifle")`. Reading takes a dot: `game.player.name`.
- `game.player`, a `shooter` and a `hit.victim` are all characters: the same kind of value, always the same value for the same one, so `hit.victim == game.player` works and one can be a key in a table (`hits[hit.victim] = 3`).
- Read input by action name (`"jump"`, `"fire"`, `"move"`, `"look"`, ...), never by key, so keyboard, mouse and gamepad all work. The action names are listed in `lore.d.luau`.
- A button of the game's own: `game.input.bind("open_map", { "F1", "LeftBumper" })` at the top of the file (never inside a function), then read it like any action. The name is lower case letters, digits and underscores, like the engine's own. Give at least one keyboard or mouse button and one gamepad button; without both, bind stops with an error (LeftBumper is the one left for games, though in a menu it also turns to the previous tab, and it is the `lock_on` button in a game that turns the "lockOn" ability on; GamepadSelect is `switch_view`, which the engine only acts on in a game that lets the player switch between first and third person). Bind each action once. An action can have directions instead: `game.input.bind("ride", { "WASD", "LeftStick" })` (or one direction, `{ "A/D", "LeftStickX" }`), read with `local x, y = game.input.axis("ride")`; all of an action's bindings are buttons or all are directions. Saving the script puts new, changed and removed actions into the running game. `game.input.pointer()` is the pointer's x and y in HUD pixels (nil when there is none; a menu set gives one), `game.input.wheel()` the wheel notches since the last tick (above 0 when rolled forward), `game.input.typed()` the characters typed since the last tick and `game.input.typedKeys()` the "Backspace", "Enter" and "Escape" pressed, in order, once `game.input.startTyping()` made the keyboard a text input (`stopTyping()`, `isTyping()`; `game.menu.textBox` does this for you), `game.input.usingGamepad()` true when the player last used a gamepad, `game.input.stepped("menu_move")` an x and y of -1, 0 or 1 on the tick a direction is pushed and again every 0.1 seconds once held for 0.4, for moving through a menu, and `game.input.label("interact")` is what to show the player for an action ("E", "A"); it is real-world, so read it in `game.onDraw`.
- The engine tells the player when their controls file is saved and read again, or is wrong. `game.input.onControlsChanged(function(change) ... end)` hears of it (`change.message` is the text), and `game.input.showControlsNotice(false)` hides the engine's notice so the game can draw its own.
- Actions can have a set of their own: `game.input.addSet("riding")` at the top of the file, then `game.input.bind("gallop", { "H", "LeftBumper" }, { set = "riding" })` is heard only after `game.input.useSet("riding")` (`useSet` takes the name `addSet` made); `game.input.sets()`, `game.input.actions("riding")` and `game.input.bindings("gallop")` list what there is. A controls page changes buttons while the game runs: `game.input.listenForButton(function(button) if button then game.input.rebind("jump", { button, "GamepadSouth" }) end end, { device = "keyboard" })` waits for the next key or button (nil when the player cancels with Escape or Start, when `seconds` (5) pass, or when you call `game.input.stopListening()`; `isListening()` says whether it waits, and every action reads as let go meanwhile), `game.input.rebind("jump", { "F", "GamepadSouth" })` keeps new buttons for the game in its own bindings file (one for keyboard or mouse and one for gamepad, of the kind the action is), `game.input.resetBindings("jump")` (or no name for all) puts back the defaults, and `game.input.usedBy("Space")` lists the actions a button presses, to warn of a clash.
- A HUD piece has `piece.hovered` (the pointer is over it), `piece.pressed` (a click began on it and is still held) and `piece:pointerAt()` (x and y across it, 0 to 1, not clamped; 0, 0 with no pointer), so a slider is `if bar.pressed then volume = math.clamp(bar:pointerAt(), 0, 1); bar.value = volume end`. `game.hud.frameGraph({ at = "top right" })` shows the last frame times, and `game.frames.rate()` and `.lowRate()` (frames a second, the 1% low) and `.lastTime()` and `.slowestTime()` (seconds) tell how the drawing goes; they differ on every computer, so read them in `game.onDraw` only.
- HUD pieces can be styled, as options when made or fields later, and `nil` puts a field back: `opacity`, `scale`, `rotation` and `transformOrigin` on every piece, `clipTo = panel` to draw only inside a box, `fontFamily` (a family from the game's `fonts` folder of .ttf and .otf files), `fontWeight`, `fontStyle`, `letterSpacing` and `textShadow = { right = 2, down = 2, blur = 4, color = "black" }` on text, and on a box `borderRadius`, `borderWidth`, `borderColor`, `gradient = { colors = { "#3a2a10", "#120c04" }, angle = 180 }`, `image`, `slice` and `boxShadow = { down = 4, blur = 12, color = "#000a" }`. `piece:animate({ opacity = 0, right = 40 }, { seconds = 0.4, ease = "ease-out", delay = 0.1, onDone = function() ... end })` moves numbers and colours there over game ticks (it keeps moving while the game is paused, so a menu can slide in); eases are "linear", "ease", "ease-in", "ease-out" and "ease-in-out".
- Whole screens (a title, an inventory, a dialogue box) are HTML and CSS in the game's `ui` folder, loaded with `local main = game.ui.load("ui/main.html")` (the starter's `ui/title.html` and `ui/title.css` are an example): `onclick="startGame"` in the HTML is answered by `main:on("startGame", function(event) ... end)`, then `main:show()` and `main:hide()`. `main:find("#play")` gives an element to change (`text`, `value`, `class`, `style`), `main.values.volume` and `main:bind("volume")` read and write inputs and settings, and `lore check` reads every screen. `ui/lore.css` is the starter stylesheet: a screen that links it first (`<link rel="stylesheet" href="lore.css">`) can use its classes (`screen`, `row`, `col`, `gap-3`, `panel`, `panel-title`, `btn`, `bar` with a `fill` inside, `tabs` and `tab`, `list-row`, `slot`, `toast`, `anim-rise`, and a theme class on `body`: `amber`, `green`, `blue`, `white`, `rose`, `violet`) instead of new CSS; read the file for the full list before writing a rule it already has. The page for it is `docs/game-ui.md` in the LORE repository, with the HTML and CSS it accepts in `docs/ui-markup.md`.
- Things placed in the level (the entries of `map.toml`, which `lore edit` writes): `game.thing("Cellar door")` finds one by the name it was given (at the top of the script is fine; a name the map lacks is an error listing the names it has) and `game.things("chest")` lists every one of a type (`game.things()` everything). A thing has `.name`, `.id`, `.kind`, `.position`, `.facing` and `thing:property("locked")` for a property from the map. `door:onUse(function(door) ... end)` makes it usable (only that does; the settings below only shape it): the engine finds the usable thing under the crosshair and in reach in either view, shows `door.useText` ("Use" until set, e.g. `door.useText = "Open"`) beside the key or button bound to `interact` (E, or Y), and calls the function on a press, or after `door.useSeconds` of holding. `door.useReach` is how close (2.5 m), `door.usable = false` switches it off. `game.player.lookingAt` is the thing that would be used now (or nil) and `game.player.useProgress` a hold's progress from 0 to 1; `game.showUsePrompt(false)` hides the engine's prompt for a game that draws its own. `lore check` uses every usable thing once. Zones: `game.zone("Bridge")` finds something placed as type `zone` (it is a thing like any other), `bridge:onEnter(function(who) ... end)` and `bridge:onLeave(...)` are called with whoever walks in or out (the player and every other character; compare `who == game.player`), once per crossing, and `bridge:has(game.player)` asks now. A zone is a round 2 m about the thing and 3 m high unless the map gives it `radius`, or `width` and `depth`, and `height`. `lore check` says the player walked into each watched zone and out.
- NPCs (people of the game's own): `local guard = game.npc { name = "Guard", at = "Gate" }` puts one in the world in one line. `at` is the name of anything placed in the map (place a marker of type `place` for a spot that is nothing else), a vector, or a thing; `facing = 90` turns it (degrees left; at a place it faces the way the place does). An entry of type `npc` in `map.toml` is one too, there from the first line; `game.npc("Smith")` finds either by name (a name no NPC has is an error listing those there are) and `game.npcs()` lists them all. One name is one person, and names ignore capitals ("guard" is "Guard"): make each NPC once at the top of the file (a second `game.npc { name = "Guard", ... }` is an error, so they cannot pile up in `game.onTick`) and number a crowd, `for i = 1, 5 do game.npc { name = "Villager " .. i, at = "Square" } end`. An NPC is a character like `game.player`: it has `health`, is hurt by shots and swings (`game.onDamage`, `game.onDeath`, `hurt.victim == guard`), walks into zones and can be locked on to. It is drawn as the mannequin, standing and breathing, is solid to the player, and turns its head to the player within `guard.lookDistance` metres (5; 0 never). At health 0 it falls and lies there, no longer solid, shot at or usable; `guard:setHealth(100)` stands it up, `guard:remove()` takes it out. `guard:onUse(function(npc) ... end)` makes it usable like a thing ("Talk to Guard" until `guard.useText` says otherwise; `useReach`, `useSeconds`, `usable` as for things). Saving the script keeps its NPCs, found again by name: change `at` and save to move one, delete its line to let it go. Those placed in the map follow `map.toml` and the editor the same way.
- NPCs walk: `guard:goTo("Gate")` walks it to a place (a name in the map, a vector, a thing, or someone such as `game.player`) and returns at once; `guard:follow(game.player, { distance = 3 })` keeps it near someone until `guard:stop()` or another `goTo`. `{ run = true }` runs; `goTo` also takes `within` (metres, how close is there) and `facing` (degrees, the way to face on arriving). It finds its way round walls, crouches under low ceilings, opens doors on the way as the player does (the door's `onUse` hears `function(door, who)` with the NPC as `who`; a door with `usable = false` is locked to it), steps round people and waits rather than push, and moves with the player's own legs, so it goes only where the player could. `guard:onArrive(function(guard, where) ... end)` hears it get there; `guard:onCannotReach(function(guard, why) print(why) end)` hears a sentence such as `Guard cannot reach Gate: the door "Cellar door" is locked (...)` (with no function, it goes to the log). `guard.destination` is what it is walking to, or nil. Do not move an NPC by setting positions each tick: send it with `goTo`. `lore check` warns of a `goTo("Name")` the map has no place for.
- NPCs see and hear: `guard:onSee(function(who) ... end)` when someone comes into view (the player or another NPC; a fallen one too, `who.dead`), `guard:onLoseSight(function(who, lastSeen) ... end)` when they go out of it, `guard:onHear(function(noise) ... end)` with each noise it hears (the same `noise` as `game.onNoise`: `sound`, `position`, `loudness`, `by`, `weapon`), `guard:canSee(game.player)` now and `guard:inSight()` for everyone it sees. Sight is a cone the way its body faces (`sightDistance` 30 metres, `sightAngle` 120 degrees; 360 also sees up and down), blocked by walls and by people standing in the way; distance, fog, the dark of night (`nightSight` 0 to 1; lamps light it again), crouching and keeping still make it weaker. It hears every noise the player hears, as far (`hearing` 1; 2 twice as far), more quietly through a wall, and never its own. Blind is `guard.sightDistance = 0`, deaf `guard.hearing = 0`; each is also an option of `game.npc { }`. It looks five times a second and listens every tick. A sound a script plays once with `game.audio.playAt` in the rules is heard by NPCs too (`{ npcsHear = false }` for one they must not hear; one played in `game.onDraw` never is); played from an NPC's own function, it is that NPC's (`noise.by`). `onHear` is not told thunder, rain or running water (`game.onNoise` is). Taking someone out with `npc:remove()` tells each NPC that saw them `onLoseSight` first; someone in view falling is told by `game.onDeath`, not again by `onSee`. Do not write your own sight cones or distance checks for guards. `lookDistance` only turns the head; `sightDistance` is what it notices.
- Solid things: a thing whose map entry has the property `model` is drawn and solid (`model = "crate"`, `"barrel"` or `"door"`, or a .glb file in the game's folder such as `"models/cart.glb"`); with `moves = true` it falls, rolls, stacks and is pushed by the player walking into it (`weight = 40` sets its kilograms; above about 80 the player cannot slide it), and with `hinge = true` it swings about the edge it is placed by. In map.toml those go under the entry's `[entity.properties]`. A script reads `thing.position`, `.facing`, `.velocity`, `.moves`, `.weight` and `.resting`, and in the rules `crate:push(vector.create(0, 60, -120))` shoves one (kilogram metres a second: weight times speed) and `crate:teleport(vector.create(0, 2, 0))` puts it somewhere at rest. The same game played the same way leaves every crate in the same place. Carrying needs no code: a thing that moves and weighs no more than `game.player.carryWeight` (40 kg; `game.player:setCarryWeight(80)`) shows "Pick up" when looked at, is picked up with `interact`, held out in front, put down with `interact` again and thrown at the crosshair with `fire`; it is let go by itself if it catches on a wall. `thing.carryable = false` (or `true` for a heavy one) says otherwise, `game.player.carrying` is the thing in their hands, `game.player:drop()` makes them let go, and `game.onPickUp(function(thing) ... end)` and `game.onDrop(function(thing, thrown) ... end)` hear of it.
- Doors, lifts and platforms: a solid thing without `moves` is moved by the game. In the rules, `lift:moveTo(game.thing("Top floor"), 4)` (or a vector) slides it there over 4 seconds and `turntable:turnTo(90, 2)` turns it; whoever stands on it rides and turns with it, whoever is in the way is pushed, and it waits for someone caught against a wall. `lift.sliding` says it is on its way, `lift:onArrive(function(lift) ... end)` and `lift:onBlocked(function(lift, who) ... end)` hear of it. With `opens = true` in the map (and `model = "door"`, or any model) it is a door the player opens and shuts by using it, with no script; `door:open()`, `door:close()` and `door.isOpen` are for levers and timers, and `swing = -90` in the map changes how far and which way it swings.
- Aiming: shots and throws land where the crosshair points in either view. `game.player.aimPoint` is where one would land now and `game.player.aimBlocked` is true when cover in front of the body stops it short of the crosshair (third person only); `game.hud.onScreen(place)`, inside `game.onDraw` only, gives how far right and down of the middle of the screen a place in the world is (nil, nil behind the camera), for a second mark or a label over something.
- Seeing and moving the player: `game.player.velocity`, `.eye`, `.aim` (vectors), `.grounded`, `.movement` (`"walk"`, `"fly"` or `"noclip"`) and `.flySpeed`. Change them in the rules with `game.player:teleport(vector.create(0, 2, 0))` (feet there, optionally facing a vector second), `game.player:setMovement("fly")` and `game.player:setFlySpeed(20)` (0.5 to 200). `.crouched`, `.sprinting` and `.swimming` say what the player is doing. How they move on foot is six numbers, each read as a field and set in the rules: `game.player:setWalkSpeed(6)`, `setSprintSpeed(9)`, `setCrouchSpeed(3)`, `setSwimSpeed(2)` (metres a second; 4.5, 6.5, 2 and 1 to start), `setJumpHeight(2.5)` (metres, 1.1 to start, 0 for no jumping) and `setGravity(1.6)` (20 to start); read them as `game.player.walkSpeed` and so on. Abilities are switches, each one line in the rules: `game.player:setAbility("vault", true)` (forward and jump against a low thing gets onto it), `"climb"` (forward and jump pulls up onto a ledge, found from the level's shape with nothing to mark), `"ladders"` (forward climbs something placed in the map as type `ladder`, back goes down, jump lets go) and `"swim"` (on to start; off, the player sinks and walks the bottom). `game.player:can("climb")` asks; `setVaultHeight(1.3)`, `setClimbHeight(3)` and `setLadderSpeed(3)` set how high and how fast (1.1, 2.2 and 2.2 to start); `.onLadder` and `.climbing` say what the player is doing. Fighting has three more switches for the same call: `"block"` (holding the `block` button, right mouse or left trigger, raises the guard: `game.player.blocking`), `"dodge"` (the `dodge` button, Left Alt or B, throws the player the way they push for `dodgeDistance` metres in `dodgeSeconds`, 3.2 and 0.35 to start, `setDodgeDistance`/`setDodgeSeconds`; `game.player.dodging` is true meanwhile and what that saves them from is the game's rule) and `"lockOn"` (the `lock_on` button, Q or left bumper, holds the view on the nearest character in front, the next on another press, then lets go: `game.player.lockedOn`).
- Dice: `math.random()` (0 up to 1), `math.random(6)` (1 to 6), `math.random(3, 8)`, `game.chance(0.25)` (true one time in four), `game.pick(list)` (one thing from it, nil if empty) and `game.shuffle(list)` (new order in place, gives the list back). They are the game's own dice: the same seed, the same presses and the same starting settings (the player's `difficulty` and `fall_damage`, from their settings file) play the same game on any computer, the dice carry on when a script is saved and reloaded, and `lore check` always rolls the same. Never seed them from a clock; a new game already gets a seed by chance. `game.seed()` reads it, `game.setSeed(1234)` (or `math.randomseed`) starts the dice again for a world that is the same for everyone, and `lore run --seed 1234` plays with a seed. Rolls made in `game.onDraw` come from a second set and never move the rules' dice.
- Walking: `game.canWalk(from, to)` says whether a person can walk from one place (a vector) to another: up steps of 0.4 m and slopes of 45° at most, through gaps 0.7 m wide or more, crouching where it is low, never through a shut door. `local corners, why = game.findWay(from, to)` gives the corners of that walk as a list of vectors (draw a trail along them), or nil and why. The engine works the walkable ground out from `level.glb` and the map's solid things; there is nothing to place or bake. `lore check` warns about named places in `map.toml` that cannot be walked to from the start.
- The speed of time: `game.setTimeSpeed(0.25)` (0 to 8, anything outside is taken as the nearest end; 1 usual) and `game.timeSpeed()`. At 0 `game.time()`, timers and weather stand still but `game.onTick` still runs with a `step` of 0, so the game can hear the player and start time again.
- Difficulty is one dial of named steps, easiest first: "Story", "Standard" and "Hard", or a game's own with `game.difficulty.steps = { "Gentle", "Fair", "Cruel" }` (1 to 10, at the top of the file). Read it with `if game.difficulty.name == "Hard" then ... end`, or `game.difficulty.level` (0 easiest to 1 hardest); set it with `game.difficulty.name = "Hard"`.
- Scale a number with it: `game.difficulty.scale(20)` is 20 times 0.5 at the easiest step, 1 at the middle and 1.5 at the hardest. The middle of the dial is 1 times, not the first step: with steps `{ "Normal", "Hard" }`, "Normal" is the easiest and gets 0.5 times. Give your own ends, the number to multiply by at the easiest step and then at the hardest, either side of 1 (or one at 1) so the middle sits between them: `game.difficulty.scale(10, 1, 1.5)` keeps "Normal" at 10, `game.difficulty.scale(5, 2, 0.5)` (an easier game waits longer), and for damage the player deals `game.difficulty.scale(10, 1.5, 0.5)`. `game.difficulty.onChange(function(now, before) ... end)` hears each turn (not the start), even while paused.
- The player turns the dial in the pause menu's Gameplay tab, beside the assists "Game speed" and "Fall damage", which work at any step: do not make a difficulty menu of your own, and never lock the dial.
- The world's clock: `game.clock.dayLength = 20` (minutes of play a day lasts; 0, as made, stands still), `game.clock.time = "8:00"` (24-hour text, or a number; sets today's time as a watch is set: at the top of the file it is where the game starts), `game.clock.skipTo("8:00")` (passes time forward to the next 8:00, today or tomorrow: sleeping or waiting; the hours passed are told to `onHour`, each once, in order), `game.clock.hour` (0 up to 24), `game.clock.day` (from 1, read only; setting the time never moves it, only time passing does) and `game.clock.onHour(20, function(hour) ... end)` or `game.clock.onHour(function(hour) ... end)` for every hour. All nil until set: a game that never sets the clock has no day and night. `game.sky` draws the sun from this same clock. It stops while paused and runs fast with `game.setTimeSpeed`.
- Pausing and leaving: `game.pause()` stops time for a menu, `game.resume()` lets it go on at the speed it had, `game.paused()` is true while it is paused, and `game.quit()` ends the game (ask first). All but `game.paused()` are rules: not from `game.onDraw`. A `game.onTick` that must not act while a menu is open starts with `if game.paused() then return end`.
- The pause menu is the engine's own, on with nothing written (`game.pauseMenu.enabled = false` turns it off; `game.pauseMenu.title`, `game.pauseMenu.addRow(row)` above Quit, `game.pauseMenu.controls = false` hides the buttons a player can rebind (on the Controls tab, after its settings), `game.pauseMenu.hideControl("melee")` leaves one action off it, `open()`, `close()`, and `isOpen`, a true or false to read). There is no `menu.luau` or `pause_menu.luau` in the game: do not write a second menu system. Menus of the game's own are `game.menu`: rows `game.menu.button("Go", { onPress = fn })`, `toggle`, `slider` (`min`, `max`, `step`), `choice` (`options` required), `textBox` (`value`, `placeholder`, `maxLength`, `onFinish(text)`, `onCancel()`, `onTyping(isTyping)`; press it to type, Enter finishes, Escape puts the old words back; a gamepad gets an on-screen keyboard from the engine, nothing to write, unless `game.menu.onScreenKeyboard = false` for the game's own) and `info`, each holding its own `value` (or `get`/`set` for one that lives elsewhere) with `onChange(value)`; then `local m = game.menu.new("Title", { rows })`, `m:open()`, `m:close()`, `m:toggle()` (and `game.menu.tabs({ m1, m2 })`); a menu with more rows than fit the screen scrolls by itself. Nothing to call each tick: the menu hears the player and draws itself. Set `row.value`, `row.label` or `row.text` to change what shows (`row.value` does not call `onChange`). Open menus stack, the pause menu too: `game.menu.top()`, `game.menu.anyOpen()`. Look: `game.menu.style`, `game.menu.sounds`.
- The player's settings: `game.settings.list()` gives every setting as a table (`name`, `label`, `description`, `group`, `kind` of `"number"`, `"toggle"` or `"choice"`, `min`, `max`, `step`, `options`, `value`, `default`), `game.settings.get("volume")` reads one, `game.settings.set("volume", 40)` changes one at once (the engine saves it; never write a file), and `game.settings.reset()` puts all back (`game.settings.reset("volume")` only one). Names today: `difficulty` (0 to 100: where a new game's dial starts; turn this game's with `game.difficulty.name`), `game_speed` (50 to 100), `fall_damage`, `volume`, `music_volume`, `speech_volume`, `effects_volume`, `mouse_sensitivity`, `stick_sensitivity`, `invert_look`, `rumble`, `ui_size`, `field_of_view`, `brightness`, `upscaling`, `vsync`, `frame_rate_limit`, `reflections`. They belong to the player: change one only when the player asks, in a menu. `set` and `reset` are rules: not from `game.onDraw`; `get` and `list` are fine there.
- Fluids: `local goo = game.fluid("goo", { from = "honey", color = "green", glow = 0.3 })` at the top of the file makes (or, after a save, updates in place) a kind of fluid; at most 32, water included. Ready-made names (`water`, `oil`, `honey`, `slime`, `tar`, `acid`, `lava`, `mercury`, `milk`, `soap`, `paint`, `mud`, `blood`) need no settings. Settings, also fields to read and change (`goo.viscosity = 0.6`): `color`, `clarity`, `cloudiness`, `glow`, `shine`, `metal`, `refraction` for the look and `viscosity`, `density`, `beading`, `slippery`, `sticky`, `bouncy`, `corrosive`, `dries`, `washes`, `freezes` for how it flows; the doc comments in `lore.d.luau` give each one's range. `game.fluids.spray("water", game.player.eye, game.player.aim * 12, { litresPerSecond = 0.6, spread = 3 })` lets some out this tick (call it every tick while a button is held and it flows), `game.fluids.clear("oil")`, `game.fluids.amount("water")` (litres), `game.fluids.under(game.player)` (what a character stands in, or nil) and `game.fluids.onTouch(function(touch) ... end)` each tick a character stands in fluid, with `touch.fluid == game.fluid("acid")`, `touch.cover`, `touch.depth`, `touch.harm` (what it hurt this tick; your game decides what that costs) and `touch.seconds`. Changing a kind or spraying are rules: not from `game.onDraw`; reading is fine.
- Pools: still fluid in the level (a lake, a tank, a tub) is a pool, found by the name of its sheet: `local pond = game.fluids.pool("Pond")` at the top of the file, used from `game.onStart` or `game.onTick` (the level is not in the world before that). In the level a pool is a flat sheet with the custom property `water` set to true, laid over a hollow at the height the fluid should stand; `fluid` (a kind's name) and `amount` (0 to 1) say what it holds and how full it starts. Read `pond.name`, `pond.fluid`, `pond.level`, `pond.depth`, `pond.litres`, `pond.capacity`, `pond.brim`, `pond.overflowing`, `pond.frozen` and `pond:share("honey")`; change it with `pond:fill(litres, fluid?)`, `pond:drain(litres)`, `pond:setLevel(height, seconds?)`, `pond:splash(place, { litres = 3, speed = 5 })`, `pond.fluid = game.fluid("lava")`, `pond.level = 2` and `pond.litres = 500` (rules: not from `game.onDraw`; done on the next tick). Sprayed fluid that lands in a pool joins it, kinds mix (a kind with `mixes = false`, as oil, tar and mercury are, lies as a layer of its own: the lightest is on top, is what is seen, is `pond.top`, and runs over the rim first), a full pool runs over its rim, and a character swims in it by its `density` and `viscosity`. `game.fluids.pools()` lists them, and after them any hollow with no sheet that became a pool because fluid was poured into it (named by its place, `"pool 4"`); a touch has `touch.pool` and `touch.submerged`. `game.fluids.poolAt(place)` gives the pool a place is in or nil (check for nil). `game.fluids.onOverflow(function(pool) ... end)` is called once when a pool starts to run over, `game.fluids.onOverflowEnd` once it has stopped, and `game.fluids.onPoolFormed` when a hollow with no sheet becomes a pool.
- Shaders: a game can have shaders of its own in a `shaders` folder, in WGSL, each one function. `game.shaders.screen("gray")` turns on the screen effect `shaders/gray.wgsl` (`fn screen(in: ScreenIn) -> vec3f`); `game.shaders.surface("glow", "Roof Tiles")` turns on the surface shader `shaders/glow.wgsl` (`fn surface(in: SurfaceIn) -> Surface`) for the level's material named `Roof Tiles`. `game.shaders.fluid("pulse", "slime")` turns on the fluid shader `shaders/pulse.wgsl` (`fn fluid(in: FluidIn) -> Fluid`) for a kind of fluid, wherever that kind is: pools, puddles and drops. Values are declared with `//! param` lines and set with `shader:set("name", value)`, even from `game.onDraw`. `lore check` compiles every shader. The page is https://tahuffman1s.github.io/LORE/docs/shaders.html.
- `print()` goes to the terminal, not the window; the new game's welcome and jump count are on the window with `game.hud.text`.
- Sound: `game.audio.play("gunshot")` plays a sound that is as loud wherever the player stands (music, menus, announcements), and `game.audio.playAt("gunshot", vector.create(x, y, z))` plays one from a place in the world, in metres with y up. Options go in a table after that: `{ volume = 0.5, pitch = 1.2, loop = true }`, and `range = 30` (metres) for `playAt`. Both give back a sound; keep it only to stop it later with `sound:stop()`. `game.audio.stopAll()` stops every sound the script has played; a save does not stop sounds, and the reloaded script no longer holds the old sounds, so call it in `game.onReload` if the script starts looped sounds outside `game.onStart`. A sound is a WAV file in the `sounds` folder, named without the folder and `.wav`: `sounds/ui/click.wav` is `"ui/click"`. The engine's starter sounds need no file: `"footstep"`, `"gunshot"`, `"landing"`, `"dry-fire"`, `"reload"`, `"explosion"`, `"impact"`, `"splash"`, `"splash-small"`, `"wade"`, `"swim-stroke"`, `"surface"`, `"bubbles"`, `"drip"`, `"sizzle"`, `"thunder"`, `"thunder-far"`, `"menu-move"`, `"menu-choose"`, `"underwater"`, `"rain"`, `"wind"`; a file with one of those names replaces it. Only WAV or Ogg Vorbis loads; sound files are binary, so the person supplies them. Call these inside a `game.on...` function, not at the top of the file. A name that is not a sound is a script error naming the nearest one, and `lore check` fails on a sound file that cannot be read. Nothing is played during a check. Voice lines go in `sounds/speech` (`sounds/speech/greeting.wav` is `"speech/greeting"`): they follow the player's "Speech volume" slider (`speech_volume` in `game.settings`), not the effects one, with no code from you (only files inside the folder: a sound called just "speech" is an effect); music in `sounds/music` follows the music slider the same way.
- Engine sounds and noises: The sounds the engine plays by itself can be turned down, off or swapped: `game.audio.setVolume("footstep", 0.3)` (0 off, 1 as now, up to 4; `getVolume(name)` reads it), `game.audio.replace("footstep", "boots-on-wood")` (and `replace("footstep", nil)` to undo); the noise is still made, only the playing changes (a replacement with no sound ready plays the engine's own). These settings, `setStride` and `setStepLoudness` are kept when the script is saved and reloaded, even if the line that set them is gone. Footsteps follow the player: `game.player:setStride(1.5)` (metres between steps, 2 to start; `game.player.stride`) and `game.player:setStepLoudness(0)` (0 silent and unheard, 1 as now, up to 4; `game.player.stepLoudness`). `game.onNoise(function(noise) ... end)` hears every noise the game makes as it happens, with `noise.sound`, `position`, `loudness`, `heardWithin`, `byPlayer`, `weapon` (the weapon's name for a shot, dry click or reload, else nil) and `by` (a Character: `game.player` for the player's own, nil for thunder and the like); return `false` from it to stop the engine playing that one.
- Variables at the top of the file start over every time the file is saved and reloaded. To keep values across a reload, put them in a table from `game.keep`: `local saved = game.keep("saved", { best = 0 })`, then `saved.best += 1`. Change what is inside the table; `saved = {}` would replace it with a table that is not kept (empty it with `table.clear(saved)`), and `local n = saved.n` copies the number, so change `saved.n` itself. Use the same name on every save. It holds numbers, text, true and false, `game.player` (also as a key) and tables of those, not functions. It lasts until the game is closed, not after.
- The script is sandboxed: no file access or network.
- The level is `level.glb` in this folder: one glTF Binary file, exported from Blender or another 3D tool (File > Export > glTF 2.0, format glTF Binary), in metres with +Y up. It is a binary file, so do not edit it as text; the person exports it. `lore check` loads it and says what to change in the export if it cannot be read. It is drawn in its materials' colours and every shape in it is solid: the player walks its floors and ramps and is stopped by its walls. Empty objects in it whose names begin with `spawn` are where the player starts while `map.toml` has no spawn point. `lore check` starts the player at each spawn point and warns about one with no floor under it. Without the file, the game is played on the engine's flat test floor.
- What is placed in the level is `map.toml` in this folder (there is none until something is placed): TOML with `version = 1` and one `[[entity]]` each with `id` (any text no other entity has; never change one), `type`, optional `name`, `position = [x, y, z]` in metres, optional `facing` in degrees turned left from -Z, and optional `[entity.properties]` of text, numbers and true or false. The player starts at one of the entities with `type = "spawn"`, looking the way it faces; once there is one, the level's own spawn markers are not used. `lore edit` writes the file and it can be edited as text; a running game reloads it on save, and `lore check` gives the line of a mistake. Scripts cannot read it yet.
- The game starts from `main.luau`. Split a growing game into files: `local weapons = require("./weapons")` runs `weapons.luau`, the file beside the one that asks, once, and gives back what that file returns (end it with `return weapons`; a file that returns nothing gives nil, which suits one that only adds `game.on...` functions). Paths start with `./` (beside the file that asks) or `../` (the folder above), use `/` for folders (`"./weapons/rifle"`), leave `.luau` off, and cannot leave the game's folder. Files cannot require each other in a circle. Saving any file reloads the whole game.
- A script error message names the file and the line and says what to try. Follow it before guessing.

## What the engine cannot do yet

LORE is early and grows with each version. `lore.d.luau` is the only list of what exists today. If a request needs something that is not in it, say so plainly; do not invent API. Running `lore run` after updating LORE refreshes `lore.d.luau` with whatever is new.

## Style

- Luau, four-space indent, `camelCase` names, one idea per function.
- Write comments and printed text for someone new to programming.
